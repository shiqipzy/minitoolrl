# 运行指南

从包含 `pyproject.toml`、`README.md` 与 `minitoolrl/` 的项目根执行。本地为 `D:\Projects\learn_llm\minitoolrl`；GPU 主机可以放在任意目录。

## 本地没有 GPU：只做校验与交付

本地不运行 SFT、GRPO、模型评测或 GPU 短测。以下三条命令只需 Python 3.10+ 标准库，不必先安装 torch：

```powershell
cd D:\Projects\learn_llm\minitoolrl
python -m minitoolrl.data.input_bundle --verify
python -m minitoolrl.train.run_experiment --stage plan
python -m minitoolrl.train.run_experiment --stage pack
```

`dist/tool_composition_qwen3_20261014_v2/` 中生成两个上传包：`minitoolrl_source.tar.gz`（当前源码与文档）与 `full_chain_inputs.tar.gz`（当前输入）。旁边的 manifest 用于核对输入身份。打包不创建训练运行，不包含历史模型、旧日志、源码目录下散落的数据或缓存。

GPU 部分需要另外准备 Linux GPU 主机。默认计划使用两张支持 bf16 的 NVIDIA GPU：一张做 DeepSpeed 训练，另一张常驻 vLLM 采样。只有一张卡时不能运行训推分离的 GRPO 主链与部署短测，入口会明确报错；显存是否够用以 `preflight` 实测为准，当前没有本运行的 GPU 耗时或显存成绩。

输入位于 `minitoolrl/artifacts/research/full_chain_all_restock_20261011_v1/inputs_bundle/`，含 20 个输入文件及运行记录。训练只读取一份 4500/240 条 SFT 数据。入口为 `run_experiment`，流程版本为 `deepspeed-vllm-engineering-qwen3-v5`。

输入是只读引用：`init` 把输入包复制进运行目录一次并逐文件核对清单哈希，此后所有阶段只读取它，不改写输入内容、不原地增删字段。训练产生的 token、掩码、优势和采样概率都只在内存中使用，不落盘；落盘的只是后续阶段真正要读的东西（检查点、逐步日志、曲线、清单、报告）。

[input_bundle.py](../data/input_bundle.py) 只核对已有输入包的版本和文件身份，不生成数据、不执行工具。`--verify` 与训练启动使用同一个文件核对入口。`input_protocol.json`、`consistent_inputs_manifest.json`、`validation.json` 由程序读取。

SFT 轨迹在生成时执行工具并保存返回。修改生成脚本后重新生成输入包，并用 `--verify` 核对文件身份；输入准备和训练启动不另做整包业务复查。

需要重建已有整包数据时，使用 [rebuild_inputs.py](../data/rebuild_inputs.py)，明确指定新的输出目录：

```bash
python -m minitoolrl.data.rebuild_inputs --source /path/to/source_bundle --output /path/to/new_bundle --tokenizer /path/to/local_tokenizer
```

这是已有数据的重建入口，要求输入目录包含 `inputs_manifest.json`；它恢复任务并调用 `build_sft.build_trajectory()` 执行工具，最后将对话逐行写入 JSONL。基础 SFT 的镜像直接复制本次已生成的文件。现有输入包可直接使用，无需再次构建。

`plan` 显示主链、工程性能测量、评测任务数、数据预算和时间上限，不加载模型。默认双卡包含一次 SFT、一次 GRPO、三组各一次续训，以及单/双 rank SFT 短测和一次 GRPO 训推分离短测。完整设计与目的见[训练与评测](训练与评测.md)。

## 上传到 GPU 主机并初始化

将两个 `.tar.gz` 上传到主机的 `/root/autodl-tmp/`，可用云平台文件上传，也可从本地用 SSH 信息执行（替换端口和主机名）：

```powershell
scp -P 端口 dist/tool_composition_qwen3_20261014_v2/*.tar.gz root@主机名:/root/autodl-tmp/
```

以下命令全部在远程 Linux 终端执行。新建空项目目录，解开源码包：

```bash
mkdir /root/autodl-tmp/minitoolrl_qwen3
cd /root/autodl-tmp/minitoolrl_qwen3
tar -xzf /root/autodl-tmp/minitoolrl_source.tar.gz
nvidia-smi
```

先在云镜像中安装与驱动匹配的 CUDA 版 `torch==2.13.0`（安装命令按 [PyTorch 官方安装页](https://pytorch.org/get-started/locally/) 和镜像说明选择）。这是 vLLM 0.31.0 要求的版本，不能用 CPU 环境的 `2.12.1`；只安装 CPU wheel 也无法训练。**CPU 与 GPU 是两套互斥的版本组合**：`.[cpu]` 固定 torch 2.12.1 + transformers 4.57.6，`.[gpu]` 固定 torch 2.13.0 + transformers 5.x（vLLM 要求 `>=5.10.4,<5.18.0`），同一个环境里装不了两套。本地 CPU 环境不要复制到主机。

```bash
python -m pip install -e ".[gpu]"          # torch 2.13.0、transformers 5.x、deepspeed==0.19.7、vllm==0.31.0、pyzmq
# 等价写法：python -m pip install -r requirements-gpu.txt
python -c "import torch, deepspeed, vllm; print(torch.__version__, torch.cuda.is_available(), torch.cuda.device_count()); assert torch.cuda.is_available()"
RUN=/root/autodl-tmp/tool_composition_qwen3_20261014_v2
INPUTS=/root/autodl-tmp/full_chain_inputs.tar.gz
python -m minitoolrl.train.run_experiment --stage init \
  --run-dir "$RUN" --inputs-tar "$INPUTS" --world-size 2 --gpus 0,1
```

`--gpus` 是有序列表：训练进程占第一个，vLLM 采样进程占第二个。传 `--gpus 1,0` 时训练落在物理卡 1、采样落在物理卡 0，两者始终分开；只有一个卡号时 GRPO 阶段会直接报错，不会悄悄把训推放到同一张卡上。

`deepspeed` 使用 torch 自带的 CUDA 运行时，不需要单独安装 CUDA toolkit；`vllm` 会带自己的依赖，若它试图替换 torch 版本，先装 vllm 再核对上面那行打印的 torch 版本与 `cuda.is_available()`。

也可复制完整输入目录，使用 `--inputs-root /path/to/inputs_bundle`。init 创建协议和输入清单，固定卡数、SFT 预算、GRPO 遍历次数、工程短测长度和时间上限。之后不必重复传这些参数；若显式传入不同值，入口拒绝执行。单卡仅能执行 SFT 阶段；完整 GRPO 训推分离与成对性能测量要求双卡，并在 init 固定 `--world-size 2`。

应使用未有训练协议的运行目录。初始化不覆盖已有协议、模型或成绩。

## 固定官方底座

底座使用模型自带的官方 tokenizer 与聊天模板，统一设置 `enable_thinking=False`，没有自定义模板文件或覆盖参数。模板 SHA256 为 `a55ee1b1660128b7098723e0abcd92caa0788061051c62d51cbe87d9cf1974d8`。

模型是 `Qwen/Qwen3-0.6B`，revision 为 `c1899de289a04d12100db370d81485cdf75e47ca`，权重 SHA256 为 `f47f71177f32bcd101b7573ec9171e6a57f4f4d31148d38e382306f42996874b`。

```bash
python -m minitoolrl.train.run_experiment --stage fetch_base \
  --run-dir "$RUN" --base-dir /root/autodl-tmp/Qwen3-0.6B
```

如果主机还没有本地底座，省略 `--base-dir` 让入口尝试下载；入口使用 Hugging Face 的公开下载 API，按固定 revision 下载。无论来源都核对固定权重哈希及官方模板哈希。模型 pin 同时记录输入版本和流程版本，后续阶段再次核对实际权重。

## 本地检查将要执行的命令

初始化后可以查看每个阶段的实际子命令：

```bash
python -m minitoolrl.train.run_experiment --stage sft --run-dir "$RUN" --dry-run
python -m minitoolrl.train.run_experiment --stage arms --run-dir "$RUN" --dry-run
python -m minitoolrl.train.run_experiment --stage engineering --run-dir "$RUN" --dry-run
python -m minitoolrl.train.run_experiment --stage evals --run-dir "$RUN" --dry-run
```

这些命令不会启动模型训练或评测。evals 的 dry-run 会准备评测目录与协议，应在当前运行目录中使用；它不生成成功阶段标记。准备阶段用 `plan` 查看，`pack/init/fetch_base/package` 不接受 dry-run。

## 执行完整项目

以下逐条命令会实际使用计算资源。先确认计划中的预算，再在准备好的 GPU 主机运行：

```bash
python -m minitoolrl.train.run_experiment --stage preflight --run-dir "$RUN"
python -m minitoolrl.train.run_experiment --stage sft --run-dir "$RUN"
python -m minitoolrl.train.run_experiment --stage grpo --run-dir "$RUN"
python -m minitoolrl.train.run_experiment --stage arms --run-dir "$RUN"
python -m minitoolrl.train.run_experiment --stage engineering --run-dir "$RUN"
python -m minitoolrl.train.run_experiment --stage evals --run-dir "$RUN"
python -m minitoolrl.train.run_experiment --stage analysis --run-dir "$RUN"
```

preflight 检查目标 GPU 环境：`smoke` 核对进程组通信，`memory` 按目标长度和累积配置运行 3 次更新并报告每卡峰值显存，阈值默认 23 GB，可在 init 时用 `--max-gb` 按目标硬件设置。该阶段不调用开发测试，不要求测试报告或测试源码哈希。

sft 全程只训练一段，完整终点保存后做开发集自主执行；grpo 从该 SFT 终点开始，训练进程单卡、采样为第二张卡上的常驻 vLLM 进程，每次有效更新后同步权重；arms 从同一 G0 开始各自独立续训。engineering 执行单/双 rank SFT 和 GRPO 训推分离性能测量，最后汇总工程报告；探针模型不成为后续起点。

evals 覆盖 SFT、G0 和三组终点：每个模型 360 条组合题、372 条通用题、60 条长任务，以及固定 24 世界各 16 次采样。analysis 在配额完整且工程证据完整时生成组合比较、分布式报告和统一结果页。

## 中断、重试与预算

```bash
python -m minitoolrl.train.run_experiment --stage status --run-dir "$RUN"
python -m minitoolrl.train.run_experiment --stage package --run-dir "$RUN"
```

完成阶段有 `<stage>_status.json`，再次调用会跳过，不重复花费训练时间。失败写入 `<stage>_failure.json` 并保留日志，不产生成功标记。

SFT 若已完成全部训练、仅开发评测中断，再次调用复用完整终点并补齐开发评测。arms 若前面分支已完整完成，则复用其 summary 和终点，继续后续分支。正式评测和开发诊断记录工具顺序、说明、聊天模板、政策、预算、采样参数以及模型和输入身份；条件一致时保留已完成轨迹，重试只补齐配额。条件改变或已有轨迹缺少上下文记录时明确报错，新的评测写独立目录。已开始但未完成的训练或工程短测不会自动覆盖，也不把保存的推理权重假称为带优化器状态的断点续训；先检查中断原因，再在新的运行目录执行修订预算。

默认主 SFT 2 epoch/564 更新，G0 两次遍历/240 迭代，各续训组 144 更新。训练超时提前停止时，不接入正式模型链。可在 init 前通过 `--sft-seconds`、`--grpo-seconds`、`--arm-seconds`、`--probe-seconds` 设置目标硬件的时间上限；训练量由 `--sft-epochs`、`--grpo-passes` 确定。时间上限不是实际预计耗时，实际使用量见 `budget.json`。

## 数据目录的用途

给人阅读的入口是[实际任务示例](项目说明.md#一条实际训练记录)、本指南和运行后的 `eval/report.md`；JSONL、检查点和哈希清单由程序读取。

| 内容 | 谁读取、为什么保存 | 是否上传 |
|---|---|---|
| 当前 `inputs_bundle/data/sft_*` | SFT 读取题目、调用、真实返回；世界快照和断言用于复查任务 | 由输入包上传 |
| 当前 `inputs_bundle/data/rl_train.jsonl` | GRPO 从初始世界开始采样，不读取参考调用作为模型输入 | 由输入包上传 |
| 当前 `inputs_bundle/inputs/c_recipe`、`control` | 三组续训记录、位置日程、共同验证和通用评测题目 | 由输入包上传 |
| 当前 `inputs_bundle/inputs/comp_suite`、`long` | 组合与长任务评测 | 由输入包上传 |
| 当前 `inputs_bundle/inputs/sft_rec` | 冻结输入包内的基础 SFT 镜像；校验器检查一致性，训练只读 `data/sft_*` | 冻结包保留镜像 |
| 运行目录的 checkpoints、JSONL、manifest | 后续训练、评测重试、曲线和失败分析；不是要求逐文件人工阅读 | 训练后按需回传 |
| `data/pools`、`data/sft_rec` | 已于 2026-10-18 清理；当前入口与测试不读取它们 | — |
| 九月 `full_chain_ddp_20260923_v1` 的 models、runs、research 目录 | 已于 2026-10-16 按用户要求移入回收站；不作为当前运行的起点或成绩 | 不上传 |
| `artifacts/inspection`、`validation` | 人工检查输出和历史验收记录；不用于当前运行 | 不上传 |

输入包里的 `token_stats` 是准备时统计，训练器仍按实际 tokenizer 重新编码并统计；`assertion_pass_ratio` 是准备记录中的诊断字段，不能当作模型成绩。冻结文件不原地删字段或去重，避免更改输入身份。新数据的生成入口要求明确指定新的输出目录，不默认往源码目录继续写数据。
