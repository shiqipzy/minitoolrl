# 训练与评测

入口为 `python -m minitoolrl.train.run_experiment`。项目同时回答组合泛化的实验问题，并提供工具环境、后训练和分布式训练的实现与验证证据。输入版本为 `all-restock-v1-20261011`，运行标识为 `tool_composition_qwen3_20261014_v2`。当前尚未启动完整 GPU 训练。

## 完整流程与各阶段目的

```text
官方 Qwen3-0.6B
  → 一段工具能力 SFT → SFT 基线
  → 学生自主采样 GRPO → G0 基线
  ├─ C_blocked：分解任务与回放，分块续训
  ├─ C_mixed：相同分解任务与回放，混排续训
  └─ U_mixed：六类基础任务，匹配监督预算续训
  → SFT、G0、三个分支共同参加评测与失败分析

工程性能测量
  ├─ 同官方底座的单 rank 与双 rank SFT 成对短测
  └─ GRPO 训推分离短测：DeepSpeed 训练卡 + vLLM 采样卡
```

| 工作 | 要回答的问题或展示的能力 | 直接证据 |
|---|---|---|
| 环境与数据实现 | 题意、工具状态变化、训练轨迹、奖励是否一致；是否存在组合泄漏 | 生成器测试、按订单事实核对、遗漏回补与组合隔离测试 |
| SFT | 能否从训练轨迹学会多轮工具调用，监督是否只作用于正确输出 | 损失、验证集指标、60 条开发任务的自主执行 |
| GRPO | 二值任务奖励能否提供学习信号、相对 SFT 有何变化 | 成功/失败采样组、零信号比例、实际更新、开发曲线、G0−SFT 对照 |
| 三组续训 | 数据内容与训练顺序怎样影响未见组合 | 共同 G0、分解任务数据与更新日程、配对评测 |
| 分布式性能测量 | 单双卡训练和训推分离的实际吞吐、耗时与显存 | SFT 单/双 rank 短测、DeepSpeed/vLLM GRPO 短测、loss/梯度范数差异 |
| 失败分析 | 漏做、多做、参数错误分别出现在哪里 | 自主执行轨迹、分任务族诊断 |

## SFT 与 GRPO 的共同起点

SFT 训练轨迹包含题目、参考工具调用和真实工具返回，是正式交给模型学习的完整操作过程。各阶段使用的数据来源如下：

| 使用阶段 | 轨迹来源 |
|---|---|
| 基础 SFT | 六类基础任务按业务规则给出参考调用，再实际执行并保存工具返回；定义见 [tasks.py](../env/tasks.py)，轨迹记录见 [build_sft.py](../data/build_sft.py) |
| C_blocked、C_mixed | 六类基础任务记录，加上 [decomposition_tasks.py](../data/decomposition_tasks.py) 定义的信用补偿工单、部分退款通知分解任务；全部使用参考调用执行后的记录 |
| U_mixed | 六类基础任务的参考调用执行记录 |
| GRPO | 读取已准备的任务，由当前模型现场生成调用、执行工具并获得奖励；不把参考轨迹加入采样组 |

当前 SFT 数据在开训前已经生成，工具调用在生成轨迹时执行并保存返回。训练器读取保存好的题目、调用和工具返回；`input_bundle --verify` 只核对输入版本和文件身份。业务规则与训练日程在修改生成脚本时通过测试核对，训练不另做整包业务复查，也不在每次 SFT 更新时重新执行参考调用。

初始 SFT 数据从零生成，不需要已有训练轨迹：

1. `build_splits.py` 按任务类别和种子调用 `tasks.generate_instance()`。
2. `generate_instance()` 调用 `state.make_world()` 生成订单、客户和库存，再按任务规则写出题目、参考调用与评分要求。退款回库统一使用 `restock_order_plan()` 处理全部可回库商品。
3. `build_splits.py` 将这些任务写入任务池 `sft.jsonl`。此时有调用列表，还没有逐轮工具返回。
4. `build_sft.main()` 读取任务池，调用 `build_trajectory()`。后者复制初始场景，按顺序直接执行 `tools.execute()`，将调用和真实返回存入 `turns`。需要纠错的轨迹先执行错误 ID 调用，再执行正确调用。
5. `build_trajectory()` 返回记录；`build_sft.main()` 用 `json.dumps(record) + '\n'` 写入 `sft_sft.jsonl`，每行是一条完整训练轨迹。
6. 训练时，`train_sft.py` 读取 JSONL，将记录交给 `sft_dataset.build_sequence()`。后者直接使用 [chat_format.py](../chat_format.py) 中的 `ChatFormat` 和 `MultiTurnSequence`，按模板渲染消息、追加 token 并标记监督位置；训练器据此生成 labels，`collate_sft()` 用 PAD 在同批短序列的末尾补齐至该批最长序列的长度，填充位置不参与损失计算。

JSONL 中已经保存了完整轨迹。第 6 步发生在训练器读取数据时：将保存的内容按聊天模板编码为模型接收的整数 token 序列，并标记损失位置；每条记录在训练开始准备时编码一次，结果保存在内存中供各训练批次使用。

实际题目、工具调用、返回与监督关系见[一条实际训练记录](项目说明.md#一条实际训练记录)。token 编号只在训练准备时进入内存，无需额外保存一份完整数组供人阅读。

上述初始生成入口是 [build_splits.py](../data/build_splits.py) 和 [build_sft.py](../data/build_sft.py)。[rebuild_inputs.py](../data/rebuild_inputs.py) 是另一个用途明确的入口：需要沿用已有任务与训练顺序时，它读取已有整包数据，重新执行并写到新目录。当前准备好的输入包可直接用于训练。

模板同时供 SFT 和模型执行使用。文本、token 和学习目标由 `chat_format.py` 统一生成，数据生成和训练不再逐轮重渲染整段对话作比较。`grader.py` 负责模型任务完成情况与 GRPO 奖励。

| 阶段 | 默认预算与参数 | 产物 |
|---|---|---|
| 工具能力 SFT | 4500 条训练、240 条验证；连续 2 epoch，共 9000 次记录曝光、564 次更新；microbatch=2，grad_accum=8，全局 batch=16；lr=2e-5，seed=1，最大序列 4096；DeepSpeed ZeRO-2（bf16 计算、fp32 优化器状态、不 offload） | `SFT`，路径 `sft/endpoint/` |
| GRPO | 240 条任务池，完整遍历 2 次；每次 2 个任务、每任务 4 条学生轨迹，共 240 次采样迭代、1920 条轨迹；单个训练进程，采样由第二张卡上的常驻 vLLM 进程完成；lr=1e-6，seed=17 | `G0`，路径 `grpo/main/models/final/` |

SFT 全程只创建一次 AdamW，weight_decay=0.01、grad_clip=1，3% warmup 后余弦衰减至峰值学习率的 0.1。两轮共享同一个优化器与学习率日程。每轮结束检查验证集。终点按预定完整预算选定，不按测试成绩选模型。每轮有 281 个完整更新和 1 个含 4 条记录的尾批，共 282 次更新。一次全局更新在 DeepSpeed 内只做一次梯度裁剪和一次优化器步：损失按整个更新组的全局监督 token 数归一化，每个 rank 恰好反向 `gas_local` 个 microbatch，真实 microbatch 不足的一侧用零损失补齐（不复制真实样本）。后端把每个真实 microbatch 的损失乘以 `gas_local × world_size`，补偿 DeepSpeed 按累积步数缩放及跨 rank 平均；零损失微步仍传入零损失。

只监督应生成的 assistant token；用户提示、工具返回和纠错训练轨迹中的注入错误调用不参与损失。训练读取固定版本 Qwen3 官方 tokenizer 模板，设置 `enable_thinking=False`，并将原模板随检查点保存。后续训练和评测读取同一模板。Qwen 模板重新渲染完整历史时会省略部分空思考段；本项目按轮追加官方格式，保留生成过的 token，保证 SFT 与 rollout 的前缀一致。实现见 [SFT 数据](../data/sft_dataset.py) 和 [SFT 训练器](../train/train_sft.py)。

SFT 终点另做 60 条开发任务的自主执行，报告真实任务完成率以及补偿等切片。查询过政策、调用过信用工具属于诊断量，不作为训练成功的替代，也不据此提前结束 SFT。

GRPO 奖励为最终任务成功的 0/1，优势在同任务 4 条采样内归一化。全对或全错的组没有优势信号。损失为 on-policy clipped GRPO，clip=0.2，按每条轨迹的策略 token 均值归一化；KL 与熵系数为 0；不向采样组插入参考训练轨迹。240 次迭代不等于 240 次有效更新，报告单独记录实际更新和无信号迭代。

主循环只有采样、更新、同步三件事：采样器产出轨迹，训练后端在有学习信号时完成一次更新并推进 policy_version，随后把新参数同步给采样器；零信号迭代不更新也不同步。采样与训练分卡部署：训练卡上是 DeepSpeed ZeRO-2 单进程，采样卡上是常驻 vLLM 进程，两者用 vLLM 官方 NCCL 权重传输同步。同步协议固定四步：本批采样全部结束 → 训练器完成更新 → 传入新参数并清除旧参数对应的前缀缓存 → vLLM 确认版本号后接受下一批请求；客户端对每一批生成断言 policy_version，同步失败直接结束本阶段。同步过程不落盘检查点，也不保存参数副本。每批轨迹只做一次优化器更新，损失前向计算 lp，并以同次前向的 lp.detach() 作为 old_lp，不另做无梯度前向。此时概率比为 1、裁剪不触发，分子仍保留策略梯度；采样器返回的概率只与这次前向的概率核对训推数值差异，不进入损失。

G0 只在最终预算位置保存模型，不做中途检查点；在 1/3、2/3 与最终预算位置于同一 24 条开发任务上记录曲线，曲线直接用内存中的当前策略评测。固定使用最终完整预算终点进入三组续训。两次任务池遍历是预先设定的训练量，不承诺必然改善；SFT 和 G0 都进入相同终测来检验实际作用。

## 三组续训

三组从同一 G0 独立开始，各自新建优化器、训练一次。C 两组的 prompt、世界、参考调用、断言与监督轨迹相同，只改变更新顺序。

| 组别 | 每 epoch 记录 | 日程 | 监督 token/epoch |
|---|---:|---|---:|
| `C_blocked` | 1152 | 先 576 条基础任务回放，再 576 条分解任务轨迹 | 174,225 |
| `C_mixed` | 1152 | 每次更新 8 条回放＋两个四记录分解任务组 | 174,225 |
| `U_mixed` | 1296 | 每次更新六类基础任务各 3 条 | 175,564 |

C 的回放由六类基础任务各 96 条组成；分解任务轨迹形成 144 个四记录块。每块从相同世界的独立副本发出四条需求：两条“等级信用补偿＋补偿工单”、两条“部分退款＋退款通知”。不同需求不串联执行后的状态；重复记录是明确的日程位置，不去重。

分解任务轨迹由 `decomposition_tasks.py` 定义，共 576 条，全部计入每轮训练量。这里分别训练信用补偿、部分退款及其明确要求的工单或通知，组合评测再要求模型完成训练未见的操作组合。C_blocked 与 C_mixed 的题目、场景、参考调用、工具返回和评分要求相同，只改变训练顺序。分解任务对组合表现的影响需要通过终点评测检验。

`C_mixed` 每次从六类回放各取 1 条，再从轮转的任务对各取 1 条，合计 8 条；同时加入两个分解任务组。额外任务对依次为退款回库/取消未发货、部分退款通知/盘点纠正、释放预留/等级补偿。`U_mixed` 每类 216 条，每次各取 3 条。

三组均 2 epoch、每 epoch 72 次更新、合计 144 次；microbatch=2。C 两组 grad_accum=8，全局 batch=16；U 组 grad_accum=9，全局 batch=18。三组 lr=1e-5、weight_decay=0.01、grad_clip=1、seed=17、最大序列 4096；共同验证集为 120 条。C/U 监督 token 相差约 0.77%，在 1% 容差内；记录数、输入 token 不完全相同。固定日程保持记录位置和 microbatch，不再长度分桶重排。

## 分布式训练与性能验证

生产路径只有一套训练后端和一套采样后端：训练是 DeepSpeed ZeRO-2（分片优化器状态和梯度，模型参数每卡保留完整副本；bf16 计算、fp32 优化器主权重、不 offload），采样是 vLLM。

SFT 与三组续训用 `--world-size` 控制训练进程数，默认双卡；全局 batch 不随卡数增大；rank r 处理第 r、r+N 等 microbatch，以全局监督 token 数归一化，DeepSpeed 保留各微步的梯度份额并跨 rank 求和，使单卡、双卡与参照后端采用同一次全局更新的目标。U 组 9 个 microbatch 无法均分双卡，少的一侧用零损失对齐累积边界。GRPO 的训练恒为单进程，采样进程常驻另一张卡；GRPO 短测直接使用这套部署，核对采样、更新和权重同步，并记录吞吐与耗时。

`engineering` 复用正式训练代码，记录训练性能。

| 验证 | 默认执行量 | 控制条件与解释 |
|---|---|---|
| SFT 成对短测 | 单 rank、双 rank 各 40 次更新 | 同官方底座、数据、顺序、全局 batch、完整日程；短测只截取前缀，不压缩学习率日程 |
| GRPO 训推分离短测 | DeepSpeed 训练卡+vLLM 采样卡，20 次迭代 | 从 SFT 终点独立开始，每次 2 任务×4 轨迹共 8 条；检查传参、清前缀缓存、确认版本和下一批采样，记录实际吞吐 |

短测均排除前 2 次计时，SFT 报告更新/秒、监督与输入 token/秒，GRPO 报告轨迹/小时、生成 token/秒，并报告峰值显存。每个测量同时记录墙钟秒数与 GPU 秒数（GPU 秒数 = 墙钟 × 占用卡数）。SFT 的加速比相对单 rank，效率为加速比/rank 数；GRPO 报告训推分离部署的实际吞吐、耗时和训练卡显存。

成对 SFT 日志比较逐步 loss 与梯度范数。短测不足以说明完整训练终点成绩相同。只在计划迭代全部完成、配置和数据匹配时计算比例数字。探针不生成主链检查点；GRPO 探针不做中途保存和开发集评测。

选择单卡时无法运行训推分离的 GRPO 主链和部署短测；入口会明确报错，而不是改成同卡部署后继续。


## 评测与分析

统一 episode 上限：8 轮、12 次工具调用、每轮 160 个新 token、上下文 3584 token。greedy temperature=0，top_p=0.95，top_k=0，batch_size=8。参考调用不输入模型，任务从初始世界开始自主执行。

以下三项均覆盖 SFT、G0、C_blocked、C_mixed、U_mixed 共五个终点。

| 评测 | 每模型数量 | 用途 |
|---|---:|---|
| 三族组合留出 | 180 个世界，各 A/B 两种表达，共 360 条 | 组合泛化、表达稳定性 |
| 通用协议 | 372 条 | 基础能力保留、补偿分层与目标任务切片 |
| 双订单退款 | 60 条双订单批量退款 | 核对两个订单各自的查询、退款金额和状态 |

评测统一通过 vLLM 采样，使用相同模板、episode 上限、解析器和多轮执行逻辑（`rollout_pool`）。每个正在进行的评测任务占用一张卡，逐任务排队。

组合集每族 60 个世界；退款加信用任务按三种等级及是否达到补偿上限分为六层，每层 10 个世界。A/B 共享世界、参考调用和断言，仅改变措辞。批量退款不并入三族组合成绩。

主分析报告分族成功率、A/B 单表达均值、两种表达均成功率、至少一种成功率及失败类型。置信区间按任务族分层、按世界配对 Bootstrap，10,000 次抽样；同一世界的 A/B 作为一个单元，不当作两个独立世界。比较为 G0−SFT、C_mixed−U_mixed、C_mixed−G0、C_blocked−G0、C_mixed−C_blocked、U_mixed−G0。训练随机种子只有一组，区间衡量评测世界的不确定性，不代表多次训练的不确定性。

三族组合、通用集和双订单退款均保留五个模型，不遗漏任何分支。缺失评测、超时或未完成配额会阻止生成“完整结果”。分析程序报错时阶段失败，不将错误隐藏为成功标记。

## 执行量与预算

默认双卡完整项目：**5 个主训练任务＋3 个工程短测＋15 个 greedy 评测任务**。终点评测合计 3960 条 episode，另有 SFT 开发集 60 条和 GRPO 开发曲线 3×24 条，以及验证集 teacher-forcing 检查。GRPO 主链与训推分离短测都占用训练卡与采样卡；三组续训顺序执行；模型评测每卡一个任务排队。

| 子任务 | 内部时间上限 | 外层进程上限 |
|---|---:|---:|
| 主 SFT | 3600 秒 | 4800 秒 |
| 主 GRPO | 3600 秒（含保存预留） | 4800 秒 |
| 每个续训分支 | 2400 秒 | 3300 秒 |
| 每份工程短测 | 1500 秒 | 2400 秒 |
| SFT 开发评测 | 无独立内部秒数限制 | 900 秒 |
| 每个终点评测 | 1800 秒 | 2400 秒 |

时间上限用于限制异常或过慢执行，不是提前完成固定训练量的替代条件，也不是耗时预测。未完成更新/迭代预算时保留已有产物，但不接受为正式终点。配置在 init 时固定，后续阶段自动读取；若要调整预算，先更新计划并使用新的运行目录，不能混用不同预算分支。

实际时间见 `budget.json` 和日志，具体参数可在无 GPU 的机器上执行 `--stage plan` 查看。运行及恢复说明见[运行指南](运行指南.md)。实现入口为[当前运行器](../train/run_experiment.py)、[训练后端](../train/deepspeed_backend.py)、[采样后端](../train/vllm_backend.py)、[GRPO](../train/train_grpo.py)、[工程报告](../eval/engineering_report.py)、[结果汇总](../eval/current_report.py)。
